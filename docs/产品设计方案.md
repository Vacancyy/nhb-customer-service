## 2. 核心模块设计

### 2.1 意图识别 — 插件式架构 (Intent Plugin System)

**核心设计**: 每个意图 = 一个插件。系统自动注册、LLM 自动匹配、插件自治处理。

**架构优势**:
- **开闭原则**: 对扩展开放，对修改封闭。新增功能只加文件，不改旧代码
- **LLM 自动路由**: 不用写死 if-else，LLM 根据插件描述自动选择
- **插件自治**: 每个插件自己决定是否需要认证、怎么处理、返回什么
- **易于测试**: 每个插件独立测试，互不影响

#### 2.1.1 插件接口定义

```typescript
// lib/intent/plugin.ts

export interface IntentPlugin {
  // 元数据（用于 LLM 匹配）
  id: string;                    // 唯一标识：'knowledge_qa'
  name: string;                  // 插件名：'知识库问答'
  description: string;           // 详细描述
  keywords: string[];            // 触发关键词
  examples: string[];            // 示例问题
  requiresAuth: boolean;         // 是否需要身份认证

  // 执行逻辑
  handler: IntentHandler;        // 处理函数
}

export interface IntentHandler {
  (params: {
    message: string;
    period?: number;
    userId?: string;
    context: ConversationContext;
  }): Promise<IntentResult>;
}

export interface IntentResult {
  reply: string;
  needsFollowUp?: boolean;
  followUpQuestion?: string;
  metadata?: Record<string, any>;
  newPeriod?: number;            // 可选：更新期数
}
```

#### 2.1.2 插件注册中心

```typescript
// lib/intent/registry.ts

class IntentPluginRegistry {
  private plugins: Map<string, IntentPlugin> = new Map();

  register(plugin: IntentPlugin) {
    if (this.plugins.has(plugin.id)) {
      throw new Error(`Plugin "${plugin.id}" already registered`);
    }
    this.plugins.set(plugin.id, plugin);
  }

  getAll(): IntentPlugin[] {
    return Array.from(this.plugins.values());
  }

  get(pluginId: string): IntentPlugin | undefined {
    return this.plugins.get(pluginId);
  }

  // 精简版，用于 LLM Prompt
  getSummary() {
    return this.getAll().map(p => ({
      id: p.id,
      name: p.name,
      description: p.description,
      keywords: p.keywords,
      requiresAuth: p.requiresAuth,
    }));
  }
}

export const intentRegistry = new IntentPluginRegistry();
```

#### 2.1.5 LLM 自动路由

```typescript
// lib/intent/router.ts

export async function routeIntent(message: string, context: ConversationContext) {
  const plugins = intentRegistry.getSummary();

  const systemPrompt = `
你是意图识别路由器。根据用户消息，选择最合适的处理插件。

可用插件列表:
${JSON.stringify(plugins, null, 2)}

历史对话: ${JSON.stringify(context.history?.slice(-3) || [])}
当前用户: ${context.userId || '未登录'}
当前期数: ${context.currentPeriod || '未指定'}

请输出 JSON:
{"pluginId": "匹配的插件ID", "confidence": 0.0~1.0, "extractedPeriod": number|null}

规则:
- 如果用户消息明显匹配某个插件，选它
- 如果是闲聊，选 knowledge_qa（它也能处理）
- 如果需要认证但用户未认证，依然选对应插件（插件内部会处理）
`;

  const decision = await llm.chat({
    model: 'gpt-4o-mini',
    messages: [
      { role: 'system', content: systemPrompt },
      { role: 'user', content: message },
    ],
    response_format: { type: 'json_object' },
  });

  const { pluginId, extractedPeriod } = JSON.parse(decision.content);
  const plugin = intentRegistry.get(pluginId);
  if (!plugin) throw new Error(`Plugin "${pluginId}" not found`);

  return await plugin.handler({
    message,
    period: extractedPeriod || context.currentPeriod,
    userId: context.userId,
    context,
  });
}
```

#### 2.2.2 "我的南京"渠道 — Token 免认证

用户从"我的南京" App 进入客服时，已携带有效 Token，无需额外认证。

```typescript
// lib/auth/wdn-token.ts

export async function verifyWodenToken(token: string): Promise<AuthResult> {
  const payload = await decryptToken(token, process.env.WDN_PRIVATE_KEY);
  if (payload.exp < Date.now() / 1000) {
    throw new AuthError('Token已过期');
  }
  return {
    authed: true,
    userId: payload.userId,
    name: payload.name,
    idCard: maskIdCard(payload.idCard),
    channel: 'wode_nanjing',
    authMethod: 'TOKEN',
    authenticatedAt: new Date(),
    expiresAt: new Date(payload.exp * 1000),
  };
}

// API: POST /api/auth/verify
export async function POST(req: Request) {
  const { channel, token } = await req.json();
  const result = await verifyWodenToken(token);
  const authSessionId = await createAuthSession(result);
  return Response.json({ success: true, authSessionId, name: result.name, idCard: result.idCard });
}
```

**Token 规范**（需与"我的南京"确认）:

- 加密方式：RSA 非对称（我方私钥解密）或 AES 对称（共享密钥）
- 载荷：`{ userId, name, idCard, phone, exp }`
- 有效期：建议 30 分钟

### 2.3 结构化知识存储 (JSONB)

**核心方案**: 利用 PostgreSQL + `JSONB` 实现多期条款的结构化存储。

每个知识点（如"免赔额"）作为一个对象，内部按 `period` 存储不同期的答案，无需维护多个文件夹。

```json
// knowledge_entries.structured_data (JSONB)
{
  "id": "",
  "question": "免赔额是多少",
  "answers": {
    "1": {
      "value": "1.5万元",
      "detail": "住院医疗年度免赔额1.5万元，重疾0免赔",
      "source": "1期条款第3.2条"
    },
    "2": {
      "value": "2万元",
      "detail": "住院医疗年度免赔额2万元，重疾0免赔",
      "source": "2期条款第3.2条",
      "diffFromPrev": "1期为1.5万元"
    }
  },
  "metadata": { "category": "policy", "updatedAt": "2024-09-01" }
}
```

**优势**:
- **LLM 对比友好**: 检索到一条记录，即可直接对比所有期数差异
- **维护简单**: 新增一期只需 `upsert` 对应 key，不需要拆分文件

### 2.4 RAG 检索管道 (Vector + JSONB)

**核心流程**: 向量匹配意图 → 返回结构化 JSON → LLM 智能组装。

```
用户问题: "1期比2期的免赔额多多少？"
  │
  ├─ Step 1: 向量化 (Embedding)
  │   └── "1期比2期免赔额..." → [0.023, -0.1, ...]
  │
  ├─ Step 2: 向量检索 (pgvector)
  │   └── SQL: ORDER BY embedding <-> 向量 LIMIT 1
  │
  ├─ Step 3: 获取结构化数据 (JSONB)
  │   └── 返回完整对象: { answers: { "1": {...}, "2": {...} } }
  │
  ├─ Step 4: LLM 智能合成
  │   └── Prompt: "根据以下 JSON 数据回答用户对比问题"
  │   └── LLM 内部计算: 2万 - 1.5万 = 0.5万
  │
  └─ Step 5: 生成回答
      └── "2期比1期多了5000元（2万 vs 1.5万）"
```

**关键技术选型**:

| 组件 | 推荐 | 理由 |
|------|------|------|
| 数据库 | **PostgreSQL + pgvector** | 同时支持关系型数据、JSONB、向量检索 |
| 向量类型 | `vector(1536)` | 兼容 OpenAI/国产 Embedding 模型 |
| 数据类型 | `JSONB` | 原生索引支持，查询性能极高 |
| 嵌入模型 | text-embedding-3-small | 语义匹配精度 |
| LLM | GPT-4o-mini / qwen-plus | 意图识别+JSON数据合成 |

### 2.5 期数推断策略 (Agentic Strategy)

**核心思想**: 避免僵硬的规则判断，采用 LLM 上下文感知 + 智能推荐策略。

**策略分层**:
1. **默认当前期**: 用户未指定默认当前期，并通过提示词告诉 LLM 当前期是什么
2. **多轮对话 (Context Aware)**: 把对话历史给 LLM，由其自动继承上下文（"那等待期呢" → 自动继承上一轮的期数）
3. **显式指定**: 用户明确提到期数（如"1期的免赔额"）时，使用用户指定的期数

### 2.6 多轮对话管理 (Session & History)

**核心策略**: 滑动窗口 (Sliding Window) + 核心状态提取 (State Extraction)

#### 2.6.1 存储选型：Redis (短期记忆)

由于 Langfuse 已负责**全量日志归档**（用于排查、评估、统计），多轮对话的**短期上下文**（最近 10 条）建议使用 **Redis** 存储：

| 优势 | 说明 |
|------|------|
| 高性能 | 内存读写，显著降低首字延迟 (TTFT) |
| 滑动窗口 | `LPUSH` + `LTRIM` 轻松保持固定条数 |
| 自动清理 | TTL (24h) 过期自动删除 |
| 职责分离 | PostgreSQL 专注业务，Redis 专注热数据，Langfuse 专注分析 |

**数据结构**:

```
Key: session:{sessionId}:history
Type: List
操作:
  LPUSH key '{"role":"user","content":"..."}'
  LTRIM key 0 9        ← 保持 10 条
  EXPIRE key 86400      ← 24h 过期
  LRANGE key 0 -1       ← 读取上下文
```

**会话状态 (Session State)**:

```
Key: session:{sessionId}:state
Type: Hash
Fields:
  current_period: 2
  user_id: user123
  auth_status: verified
TTL: 86400
```

#### 2.6.2 上下文加载策略

每次对话请求进来时，不把所有历史扔给 LLM：

1. **最近 N 条 (Sliding Window)**: 加载最近 **5-10 条**消息，保证 LLM 能理解"那个"、"免赔额呢"这种指代
2. **核心状态优先**: `current_period` 直接作为元数据注入 Prompt，不需要 LLM 从历史记录里猜

**Prompt 注入结构**:

```markdown
## System Instructions
你是宁惠保客服...

## Context Information (关键！)
- User ID: user123
- Current Period: 2 (已锁定，不要随意更改)
- Auth Status: verified

## Conversation History
```

#### 2.6.3 API 实现骨架

```typescript
// app/api/chat/route.ts

export async function POST(req: Request) {
  const { message, sessionId, userId } = await req.json();
  const redisKeyHistory = `session:${sessionId}:history`;
  const redisKeyState = `session:${sessionId}:state`;

  // 1. 加载上下文 (Redis Pipeline)
  const pipeline = redis.pipeline();
  pipeline.lrange(redisKeyHistory, 0, -1);
  pipeline.hgetall(redisKeyState);
  const [rawHistory, state] = await pipeline.exec();

  const context = {
    history: rawHistory.map(h => JSON.parse(h)),
    currentPeriod: state?.current_period,
    userId: state?.user_id,
  };

  // 2. 路由 & 执行
  const result = await routeIntent(message, context);

  // 3. 保存本轮 (滑动窗口)
  const pipelineSave = redis.pipeline();
  pipelineSave.lpush(redisKeyHistory,
    JSON.stringify({ role: 'user', content: message }));
  pipelineSave.lpush(redisKeyHistory,
    JSON.stringify({ role: 'assistant', content: result.reply }));
  pipelineSave.ltrim(redisKeyHistory, 0, 9);
  pipelineSave.expire(redisKeyHistory, 86400);
  await pipelineSave.exec();

  // 4. 更新状态
  if (result.newPeriod) {
    await redis.hset(redisKeyState, 'current_period', result.newPeriod);
  }

  return Response.json({ reply: result.reply });
}
```

## 4. 可观测性 — Langfuse 集成

Langfuse 负责 **可观测性 + 评估 + 效果量化**

### 4.1 埋点设计

```
每一次用户交互 = 一个 Langfuse Trace

Trace
├── Generation: 意图识别
│   ├── Input: 用户消息
│   ├── Output: 意图 + confidence
│   └── Metadata: { model: "gpt-4o-mini", cost: 0.002 }
│
├── Generation: 知识检索
│   ├── Input: 查询
│   ├── Output: 检索到的 chunks
│   └── Metadata: { period: 2, topK: 5 }
│
├── Generation: 回答生成
│   ├── Input: Prompt + context
│   ├── Output: 最终回答
│   └── Metadata: { model: "gpt-4o", latency_ms: 1200 }
│
├── Span: 工具调用 (业务API)
│   └── Output: API 结果
│
└── Score: 评估分数
    ├── answer_relevance
    ├── factual_correctness
    └── user_satisfaction (隐式/显式)
```

### 4.2 代码接入

```typescript
import { Langfuse } from 'langfuse';

const langfuse = new Langfuse({
  publicKey: process.env.LANGFUSE_PUBLIC_KEY,
  secretKey: process.env.LANGFUSE_SECRET_KEY,
  baseUrl: process.env.LANGFUSE_HOST,
});

async function handleUserMessage(userId: string, message: string) {
  const trace = langfuse.trace({
    name: 'ninghuibao-chat',
    userId,
    sessionId,
    metadata: { period: resolvePeriod(message) },
  });

  // 1. 意图识别
  const intentSpan = trace.span({ name: 'intent-recognition' });
  const intent = await recognizeIntent(message);
  intentSpan.end({ output: intent });

  // 2. 回答生成
  const generation = trace.generation({
    name: 'answer-generation',
    model: 'gpt-4o',
    input: buildPrompt(intent, message),
  });
  const answer = await callLLM(prompt);
  generation.end({ output: answer });

  // 3. 评分
  trace.score({
    name: 'answer_quality',
    value: await evaluateAnswer(message, answer),
  });

  await langfuse.flushAsync();
  return answer;
}
```

## 5. 效果量化与评估体系

### 5.1 评估指标金字塔

```
         ┌───────────────┐
         │  业务转化率    │  ← 投保成功率/理赔提交率
         ├───────────────┤
         │  任务完成率    │  ← 业务操作闭环比例
         ├───────────────┤
   ┌─────┤  意图识别准确率│  ← Intent F1 Score
   │     ├───────────────┤
   │     │  回答准确率    │  ← 事实正确性评分
   │     ├───────────────┤
   │     │  检索命中率    │  ← Hit@K / MRR
   │     ├───────────────┤
   │     │  检索相关性    │  ← NDCG@K
   │     └───────────────┘
   │
   │  ←── 线上指标 ──→
   │  用户满意度 / 转人工率 / 对话轮次
   │  问题解决率 (FCR)
```

**具体指标**:

| 指标 | 定义 | 目标值 | 测量方式 |
|------|------|--------|----------|
| 意图识别准确率 | Intent 分类正确率 | ≥95% | 人工抽检 + Langfuse 评分 |
| 回答事实正确性 | 回答是否包含错误信息 | ≥98% | 黄金测试集对比 |
| 检索命中率 (Hit@3) | 正确答案在前3条中的比例 | ≥90% | 离线评估 |
| 检索 MRR | 正确答案的排名倒数均值 | ≥0.85 | 离线评估 |
| 任务完成率 | 业务操作成功完成比例 | ≥85% | 线上埋点 |
| 转人工率 | 请求转人工的比例 | ≤10% | 线上埋点 |
| 首次解决率 (FCR) | 一轮对话内解决问题的比例 | ≥70% | 线上埋点 |
| 用户满意度 | 👍/👎 反馈 | ≥4.2/5 | 显式反馈 |

## 8. 关键风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 期数混淆 | 用户得到错误条款信息 | 强制 period filter + 后处理验证 + 专项测试 |
| 幻觉/捏造 | 给出不存在的条款 | RAG 限制 + "不知道就说不知道" Prompt + 事实校验 |
| 意图识别错误 | 走错处理链路 | 三层递进识别 + confidence 阈值 + 低置信度时反问 |
| 业务API超时 | 用户等待过久 | 超时兜底 + 异步轮询 + "请稍后查看" |
| 敏感数据泄露 | 合规风险 | 日志脱敏 + 最小化鉴权 + 操作审计 |
| 知识库过期 | 回答过时信息 | 版本管理 + 更新时触发自动评估 |
| Token 安全 | "我的南京" Token 泄露 | 不在日志打印原始身份信息，仅存 authSessionId |
| 人脸 API 依赖 | 第三方服务不可用 | 降级重试 + 3次失败转人工 |
| 人脸合规 | 《个人信息保护法》风险 | 采集前明确告知用途 + 验证后立即删除 |
